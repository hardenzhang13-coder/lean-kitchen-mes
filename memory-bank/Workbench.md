# 精益厨房 V3 — 工作台模块设计

> 版本：v1.1 | 2026-11-05 | 浩哥草图评审后修订（v1.0 → v1.1）
> 主用户：厨师长（杨厨）| 设备：PC 浏览器

---

## 一、设计立场

工作台是**排程业务闭环的驾驶舱**，不是系统功能导航页，也不是统计报表页。

业务闭环：

```
菜品排程 → 生产 → 售卖 → 复盘（卖得怎么样）→ 指导下一次排程 → 循环
```

杨厨每天打开工作台的真实思考顺序：**昨天排的菜卖得咋样 → 今天要做什么 → 明天该怎么调。**
页面按这个时间轴组织，不按系统模块组织。

三条产品纪律：

1. **不做无行动指向的指标**（菜品总数这类虚荣指标不做）
2. **不引入日期状态标记**（已复盘/未回录圆点等不做）
3. **未回录数据不计入统计**——"忘了录"不能被当成"卖光了"

## 二、信息架构（v1.1 定稿）

```
┌────────────────────────────────────────────────────────────────┐
│ 早上好，杨厨          2026年11月5日 周三      [门店▾ 新金食堂]     │  ← 门店切换（右上角）
├────────────────────────────────────────────────────────────────┤
│  一 11/3   二 11/4   三 11/5   四 11/6   五 11/7   六 11/8  日 11/9 │  ← 本周周日历条（当前周）
├────────────────────────────────────────────────────────────────┤
│  ▼ 当日排程复盘单（由日期条选中日期驱动）                          │
│    头部汇总：计划份数 · 售出份数 · 售出率 · 营收                   │
│    每道菜一行：菜品名 + 规格（规格份量/荤素/类别）                 │
│      售出进度条（售出 / 计划）｜ 销售状态                         │
│      销售状态 = 与计划的差额：✓ 售罄 / 剩 N 份 / 多 N 份          │
│    未回录 → 显示"未回录"占位（回录功能由浩哥实现）                 │
│    无排程 → 显示"当日无排程" + 去排程入口                         │
└────────────────────────────────────────────────────────────────┘
```

> v1.1 变更（相较 v1.0）：
> - **删除"本周统计"区块**（统计卡 + 售出率/损耗排行榜，浩哥评审后认定暂无意义）
> - **"损耗"概念取消**，与状态合并为**销售状态**：差额（计划 − 售出）即状态
>   - 差额 = 0 → ✓ 售罄（绿）
>   - 差额 > 0（剩）→ 剩 N 份（琥珀色，剩得多的标红）
>   - 差额 < 0（多）→ 多 N 份（靛蓝，加做/超售）

## 三、功能要点

### 3.1 门店切换

- 右上角 `Select` 切换器，选择结果持久化（localStorage），刷新保留
- 底层轻量方案：新增 `stores` 表，seed 预置两家：**新金食堂**、**明天吃啥首店**
- `schedules` 关联门店；当前**不做门店管理页**，历史数据默认归属第一家门店
- 排程新建/编辑需支持选择门店（复盘按门店过滤的前提）

### 3.2 周日历条

- 固定展示**当前自然周**周一~周日（前后翻周后续迭代再加）
- 点击某天切换主内容区；默认选中**今天**
- 对应"天天菜品不重样"：每天一个排程、一天一复盘，日期条就是复盘导航

### 3.3 复盘单（主内容区，也是页面全部内容）

每道菜一行：

| 列 | 内容 |
|----|------|
| 序号 + 菜品 / 规格 | 序号 + 菜品名 + 规格份量（正餐份量等）· 荤素 · 菜品类别 |
| 售出进度 | 进度条：实际售出 / 计划份数，售罄满条变绿，超售 capped 100% 显示百分比 >100% |
| 销售额 | 售出份数 × 菜品售价（无售价显示 —） |
| 销售状态 | ✓ 售罄 / 剩 N 份（差额大标红）/ 多 N 份 |

- 头部汇总 chips：计划份数 · 售出份数 · 售出率 · **营收**（依赖菜品售价字段，见 TODO）
- 排序：按售出率降序（卖得好的在上，问题菜沉底）
- 未回录日：整单显示"未回录"占位，数据不计入统计
- 当日无排程：空态 + "去排程"入口

## 四、数据模型变更

1. `schedule_items` 新增 `actual_sold_qty` DECIMAL —— 实际售出份数（可空，空 = 未回录）
2. 新增 `stores` 表：`id` / `name`（预置：新金食堂、明天吃啥首店）
3. `schedules` 新增 `store_id` 关联 stores（历史数据归默认门店）

## 五、API 规划

- `GET /api/dashboard/daily?date=&storeId=` —— 某日复盘单（排程 + 明细 + 规格 + 售出/差额）
- `PUT /api/schedules/[id]/sales` —— 售卖回录批量更新（**由浩哥实现**，字段先行备好）

> v1.1 变更：删除 `GET /api/dashboard/weekly`（本周统计区块已取消）

## 六、边界与不做

- ❌ 周统计 / 月度统计（浩哥评审：周统计暂无意义；月度归后续独立统计模块）
- ❌ 损耗字段与报损记录（差额即销售状态）
- ❌ 日期状态标记、排行榜
- ❌ 采购/库存指标上工作台（模块后续可能重构，不耦合）
- ❌ 移动端工作台（PWA 维持采购/库存落点）
- ❌ 门店管理页（stores 先 seed 预置）
