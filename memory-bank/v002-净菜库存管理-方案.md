## 一、产品目标

切配中心库存只管理净菜（净料+小料），**按份出入库**，形成闭环：

```
进行中排程 × N ──汇总──▶ 生产计划单（跨店合并切配工单，份数口径）
                              │
                    【完成生产】逐行确认（实际份数/未完成/暂不确认）
                              │ 事务：净菜入库（份+g 双单位）
                              ▼
                          当前库存（库存份数 + 库存量g）
                              │
        创建出库单（门店+排程 → 带出工单 → 按份出库 + 金额 + 是否按计划）
                              ▼
                    出库单（打印/作废回滚）──▶ 台账（份+g）
```

**Success 标准**：完成生产提交后库存立即可见（份数口径）；出库单金额与食材档案出库价链路一致；「是否按计划出库」可回答"货有没有按排程切足出足"。

## 二、前置事实（代码核实，2026-11-10）

- `ProductionPlan.cuttingJson`：按 (sourceType, sourceId) **跨店合并**的切配快照，portions = requiredQty ÷ packageSpec（round2）；行含 l1Name/l2Name/sourceCode/packageSpec/requiredQty/portions/portionsText/grossNeedJin。
- `CuttingOrder.actualQty` 字段已存在（Decimal 可空），packageSpec 已冗余在工单行。
- `net_ingredients` 统一承载净料/小料（sourceType 区分），`packageSpec` **必填**、`unitPrice`（元/斤）+ `processingFeePerJin` + `grossMarginRate` → 出库价链路完整。
- 生产计划单详情已有【完成生产】（现状 = 状态直翻，需改造为确认弹窗）。

## 三、数据模型设计

### 3.1 `cutting_orders`（改造最小化）

| 字段 | 说明 |
|------|------|
| actualQty | 已有。完成生产时由计划单**按需求量占比分摊回写**（展示级精度），status 同步置 completed / unfinished |
| status | pending / completed / unfinished（计划单回写驱动，不再由排程详情操作） |

### 3.2 `production_plans.cuttingJson`（行结构扩展，快照内演进）

每行新增确认态字段：

```jsonc
{
  // ……原有快照字段（sourceType/sourceId/sourceCode/itemName/l1Name/l2Name/packageSpec/requiredQty/portions/portionsText/grossNeedJin）
  "confirmStatus": "pending | completed | unfinished",   // 暂不确认 = 保持 pending
  "actualPortions": 12.5,                                 // 实际完成份数（completed 时必填）
  "remark": ""                                            // 未完成原因（选填）
}
```

> 计划单行 = 完成确认与入库的**唯一单位**；JSON 快照行集在生成时固化，确认态在快照内演进。

### 3.3 `prepped_stock` 净菜库存表（新表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | |
| source_type / source_id | | net / minor + 净菜 id，UNIQUE 组合 |
| **current_portions** | decimal(12,2) | **库存份数（记账主单位）** |
| **current_qty** | decimal(14,2) | 库存量（g，辅助字段；出入库时按当时封装规格换算同步累加） |
| updated_at | datetime | |

> 份为权威单位；g 独立累加（金额计算与展示用），不反推份。

### 3.4 `prepped_stock_ledger` 净菜台账（新表）

在 v001 基础上全部双单位：change_portions / balance_portions（decimal(12,2)）+ change_qty / balance_qty（g）。change_type / biz_type / source / operator 同 v001。

### 3.5 `outbound_orders` 出库单主表（新表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id / code | | OUT-YYYYMMDD-NNN（当日序号） |

### 3.6 `outbound_order_items` 出库单明细（新表）

| 字段 | 类型 | 说明 |

## 四、状态机

### 4.1 生产计划单切配行

```
pending ──完成生产提交──▶ completed（actualPortions ≥ 0，入库）
                        │ unfinished（当日终态，remark）
                        │ （保持 pending = 暂不确认，可下次提交）
计划单：无 pending 行 ──▶ 已完成；否则保持 进行中（可再次发起）
```

### 4.2 出库单

```
confirmed ──作废（Dialog 二次确认 + 必填原因）──▶ voided
  事务回滚：库存 += shipped（份+g 双单位），写 stock_rollback 台账
```

## 五、核心流程与规则

### 5.1 完成生产（生产计划单详情）

入口：生产计划单详情【完成生产】（仅 status=进行中 显示；排程详情原完成入口下线）。

弹窗「完成生产确认」：
- 数据 = cuttingJson 全部 pending 行（跨店合并口径，展示 来源门店数）。
- 列：一级分类 | 二级分类 | 编号 | 名称 | 封装规格 | 计划份数 | 计划量(g) | **实际完成份数** | 状态 | 备注
- 默认「完成」：实际完成份数输入启用，默认=计划份数，可改小（支持部分完成，≥0，最多 1 位小数）。
- 「未完成」：输入禁用，备注选填，当日终态。
- 「暂不确认」：保持 pending，留待下次（分批提交）。
- 汇总条：本次入库 N 种 / 共 P 份（Q g）· 未完成 n · 暂不确认 m。
- 提交（事务）：
  1. 更新 cuttingJson 行确认态；
  2. 净菜入库：current_portions += actualPortions，current_qty += actualPortions × packageSpec；
  3. 写台账（stock_in，双单位，source=生产入库/PPL-xxx）；
  4. 回写各店 cutting_orders：actualQty = 行实际量 ×（店需求量 ÷ 合并需求量）分摊，status = 实际量>0 ? completed : unfinished；
  5. 判计划单终态：无 pending 行 → 已完成。

### 5.2 当前库存（/inventory 默认 Tab）

- **无 KPI 汇总指标**。
- 列：一级分类 | 二级分类 | 编号 | 名称 | 类型（净料/小料） | **库存份数** | **库存量** | 最近变动。
- 份数格式：整数 "N 份"，小数 "N.N 份"；量 g ≥1000 显示「X 斤 Y g」。
- 筛选：搜索 + 一级分类宫格 + 类型筛选 + 分页（20/页）。操作入口：创建出库单。

### 5.3 创建出库单

- 第 1 步 门店 → 第 2 步 该门店 进行中/已完成 排程（卡片：编号/名称/日期/工单进度）→ 第 3 步 明细：
- 列：一级分类 | 二级分类 | 序号 | 名称 | 封装规格 | 计划份数 | 计划用量(g) | 库存份数 | **本次出库（份，可编辑）** | 行金额(元) | 状态
- 行状态：未切配（工单非 completed，红，默认 0 份）/ 量不足（库存份数 < 计划份数，橙）/ 正常。
- 默认本次出库 = min(计划份数, 库存份数)；可改 0..库存份数（step 0.5，≤1 位小数）。
- 行金额实时预览 = 出库价（档案当时值）× 份 × 封装规格 ÷ 500。
- 汇总条：共 N 行 · 计划 P 份 · 本次出库 Q 份 · **合计金额 R 元** · 未切配 M 行。
- 提交（事务）：重读库存校验 → 生成主表（total_portions/total_amount/as_planned 落库）+ 明细快照 → 扣库存（份+g）→ 写台账 → 跳详情。

### 5.4 出库单列表（/inventory Tab）

列（定稿）：**序号 | 出库单号 | 门店 | 来源排程单名称 | 出库份数 | 合计金额 | 是否按计划出库 | 状态 | 库管负责人 | 创建时间 | 操作**（详情/打印/作废）。

- 是否按计划出库：`<span class="badge green">是</span>` / `<span class="badge orange">否</span>`（as_planned 落库字段直出）。
- 状态：已出库（绿）/ 已作废（灰）；已作废单操作列只剩 详情。

### 5.5 出库单详情 / 打印 / 作废

- 头部信息：单号、门店、来源排程（编号+名称）、生产日期、库管负责人、创建时间、状态、合计金额、出库总份数。
- 明细列同 5.3（只读）+ 行金额列；未切配/量不足行底色标注。
- 打印：A4 出库单（含份数/金额/状态/签字栏）。
- 作废：Dialog 二次确认 + 必填原因 → 事务回滚双单位库存 + stock_rollback 台账。

### 5.6 出入库流水（/inventory Tab）

列：时间 | 类型 | 一级分类 | 名称 | 变动（份 + g）| 结存（份 + g）| 来源单据 | 操作人。类型筛选：全部/入库/出库/作废回滚。

## 九、边界与异常

1. **并发**：出库创建事务内条件更新（`current_portions >= ?`），影响行数 0 → 报"库存已变化，请刷新"；完成生产按行幂等（已终态行忽略）。
2. **负数/超发**：份与 g 双校验；g 仅为换算展示，不反向约束份。
3. **价格缺失**：净菜档案出库价链路任一要素缺失 → 行金额记 0 并在明细标「价缺失」（不阻断出库）。
4. **零头份**：份支持 1 位小数（如 2.5 份）；金额按实际 g 折算。
5. **档案变更**：出库单明细全部快照（名称/分类/封装规格/出库价），历史单据不受档案改动影响。
6. **计划单删除**：已确认入库的计划单禁止删除（引用检查），维持现有删除 Dialog。
