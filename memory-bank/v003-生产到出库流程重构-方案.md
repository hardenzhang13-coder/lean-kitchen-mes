## 〇、本方案相对现状的四处根本改变

| # | 改变 | 现状 | 本方案 |
|---|---|---|---|
| 1 | 生产计划单的性质 | 跨店汇总的**快照**（JSON 固化，不可改） | 切配中心的**生产批次任务单**（行可编辑，班组长定产量） |
| 2 | 库存的角色 | 不参与生产决策 | **共享池 + 全局占用**，参与净需求计算，直接决定采购量 |
| 3 | 实体划分 | 排程单 / 内部生产单 / 生产计划单 三张平行单据 | 排程单（需求）+ 生产批次单（生产）+ 出库单（配送），**内部生产单取消** |
| 4 | 出库的主体 | `store` 或 `cutting_center` 二选一 | **恒为门店**；来源可无（手工出库） |

## 一、产品目标

### 1.1 一句话

**让切配中心基于「门店需求 + 实际库存」排出可执行的当日生产批次，班组长能当场调整，并能一眼看清每个门店的履约缺口。**

### 1.2 Success Metrics

| 指标 | 现状 | 目标 |
|---|---|---|
| 计划量可调整性 | 生产计划单行不可改（只能在完成时回填实际量） | **行级可编辑**，班组长改「计划生产量」即时联动采购与缺口提示 |
| 库存对生产的影响 | **零影响**（`buildProductionPlanData` 不读 `prepped_stock`） | 库存充足 → 建议生产量下降 → **采购量同步下降** |
| 计划与实际的偏差可见性 | 靠 `actualQty` 按需求占比分摊（展示级精度） | 按批次行↔需求行关联表**精确回写**已备货量 |
| 生产决策入口数 | 建单 → 纳入 → 完成（三段割裂） | **一个批次单**（草稿 → 确认 → 完成） |
| 需求变更可见性 | 无 | 排程详情三段进度：**需求 → 已备货 → 已出库**，缺口标红 |

### 1.3 用户故事

**班组长（切配中心）**
- 作为班组长，明天 A 店要 150 份青椒丝、B 店要 80 份肉丝，我打开生产批次页，系统告诉我仓里已有 100 份青椒丝，所以只需要切 50 份——我可以直接改成 60 份多切点存着，采购量自动跟着降。
- 作为班组长，今天没有门店排程，但我需要备 50 份肉片应对周末，我在生产批次页点「自主加一行」就能加，不需要先去别处建一张单子再纳入。

**厨师长（门店侧）**
- 作为厨师长，我下周的排程被切配中心承接了，我能看到"已备货 140/150 份"，知道还差 10 份，能提前决定减份还是换菜。

**库管**
- 作为库管，A 店今天该收 230 份货，仓里只有 180 份，我出库时只能出 180，差的 50 份一眼看到缺口，不用猜。

## 二、核心业务模型

### 2.1 四层模型

```
需求层   门店排程单 ──▶ 门店级净菜需求行（需求量）
                        ↓ 纳入（N:M，可拆分）
生产层   生产批次单（一天多个，批次是主体，日期是属性）
         ├─ 需求行（可下钻到店/菜）
         └─ 自主备货行（无来源，替代「内部生产单」）
                        ↓ 完成生产 → 入库
库存层   净菜库存共享池（现有 / 已占用 / 可用）
                        ↓ 按门店需求配送（1 排程 ↔ 1 出库）
出库层   出库单（主体恒为门店；排程出库 or 手工出库）
```

### 2.2 关键概念定义

| 概念 | 定义 | 不是什么 |
|---|---|---|
| **生产批次** | 切配中心一次生产作业单元。一张生产计划单 = 一个批次。一天可有多个批次，彼此独立（不同行、不同状态、不共享进度） | 不是"一天一张计划"；不是"汇总快照" |
| **需求日** | 门店需要净菜的日期 = 排程单的 `schedule_date` | 不是生产日 |
| **生产日** | 批次实际生产的日期。常态 = 需求日 D-1，**不做强限制** | 不是需求日 |
| **占用** | 已被某批次承诺、尚未配送的库存份数。全局唯一，不可被多个批次重复计算 | 不是库存扣减（货还在仓里） |
| **自主备货行** | 批次行的一种，无门店需求来源，班组长主动决定生产 | 不是一张独立单据 |

### 2.3 数量口径单一真源

| 数量 | 归属 | 定义 | 可改者 |
|---|---|---|---|
| 需求量 | 门店需求行 | 菜品份数 × BOM 净料用量 → 份 | 门店/厨师长 |
| 可用库存 | 库存共享池 | 现有 − 已占用 | 系统 |
| 建议生产 | 批次行（派生） | `max(0, 需求 − 本行可分配到的可用库存)` | 系统算 |
| **计划生产** | 批次行 | 默认 = 建议 | **班组长** |
| 实际生产 | 批次行 | 完成生产回填 | 切配执行 |
| 已备货 | 门店需求行 | 该需求已被批次产出的份数 | 生产完成时回写 |
| 已出库 | 门店需求行 | 该需求已配送份数 | 出库时回写 |
| 出库量 | 出库单明细 | ≤ 应出量 且 ≤ 可用库存 | 库管 |

### 3.2 新建生产批次（独立页面）

**路由**：`/production-batches/new`

#### 3.2.1 功能本质

> 回答两个问题并当场展示答案：
> ① **为谁而做** — 承接哪些排程单的需求
> ② **额外做多少** — 无排程来源的自产/备货

#### 3.2.2 数据交互契约

| 动作 | 写入 | 不写入 |
|---|---|---|
| 勾选排程单 | 前端选择态 | 不写库 |
| 填写批次属性 | 前端状态 | 不写库 |
| 点【创建批次】 | `production_batches`（草稿）、批次行、批次行↔需求行关联、批次↔排程单溯源 | **不占用库存、不锁定排程单、不改排程状态** |
| 【确认批次】 | `prepped_stock.reserved_portions` 占用 | 不改已备货量 |
| 【完成生产】 | 净菜入库 + 回写已备货量 + 核销占用 | — |

**界面必须让用户知道**：创建 ≠ 占用库存（占用在确认）；创建 ≠ 锁定排程单（锁定在确认）；创建后仍可自由增删行与来源。

#### 3.2.3 布局：单页三区

```
┌─ ① 批次属性 ──────────────────────────────────────┐
│ 生产日 [今天▾]   计划时段 [早班▾]（可空）            │
└────────────────────────────────────────────────────┘
┌─ ② 为谁而做：来源排程单 ──────┐┌─ ③ 做多少：汇总 ─┐
│ 需求日[生产日+1▾] 门店[全部▾] ││ 5 种 · 450 份    │
│ 🔍 搜索                        ││ 库存覆盖 200 份  │
│ ☑ 新金食堂 11-21 · 8菜 120份 ││ 建议生产 250 份  │
│ ☑ 明天吃啥首店 11-21 · 6菜90份││─────────────────│
│ ☐ 新金食堂 11-22 · 5菜 60份  ││ 净料 需求 库存 建议│
│ ─────────────────────────────  ││ 青椒丝150 100  50│
│ ＋ 自主加一行（无排程单自产）  ││ 肉丝  80   0  80 │
└───────────────────────────────┘└─────────────────┘
```

- ② 区：排程单候选，多选；每条显示门店、需求日、菜品数、总份数、状态。

- **自主加一行**：独立于排程单选择，同屏可见可点。加完立即出现在 ③ 区。
- 就地提示（不弹窗不阻断）：需求日早于生产日 / 库存缺口 / 该时段已被其他批次占用。

| 场景 | 操作 | 结果 |
|---|---|---|

### 3.4 库存共享池与占用

#### 3.4.1 占用算法（批次确认时）

```
全池可用 = Σ(current_portions − reserved_portions)
本行可分配 = max(0, 全池可用 − 本单已分配)
本行占用   = min(需求量, 本行可分配)      → 写 reserved_portions
建议生产   = 需求量 − 本行占用
```

- **重算时机**：确认时重算（创建时的数可能已过期），提供手动重算按钮。
- **释放时机**：批次作废/删除 → 全额释放；完成生产 → 按实际产量核销。
- **跨天不清零**。
- **自主备货行不参与占用**，完成后为自由库存。

## 四、字段设计纪律（全系统规范）

### 4.1 三档分类

| 档 | 定义 | 呈现规则 |
|---|---|---|
| **决策字段** | 用户在这一屏要做的选择 | 最显眼、可编辑、给默认值 |
| **约束字段** | 决策的边界条件 | 必须有，但不喧宾夺主（max 限制/提示/汇总） |
| **历史/上下文字段** | 过去发生的事、静态档案 | **能挪走就挪走**，不上明细表 |

### 4.2 判定口诀

> **用户在这一屏做决定时，会看这个字段吗？**
> 会 → 保留；不会 → 挪走或删。

### 4.3 结构性原则

1. **档案属性不入明细表**：名称 + 分类 + 编码 + 规格 四者表达同一件事，只留「名称」；「规格」仅当影响决策时保留。
2. **一套主单位**：记账主单位是「份」。克重只在台账保留，明细表不并列。
3. **不排版字段入表**：「序号」是排版辅助，不占数据列。
4. **常量字段不入表**：恒为同一值的直接删列或降级为标题。
5. **可推导字段不重复表达**：「是否按计划出库」由明细天然表达。
6. **历史进详情，不进列表**。

### 4.4 逐页审查清单

| 页面 | 删除 | 保留/移动 |
|---|---|---|
| 出库单列表 | 序号、出库主体、是否按计划出库 | 出库单号、门店、来源排程单、出库份数、合计金额、状态、库管负责人、创建时间、操作 |
| 出库单详情表 | 一级分类、二级分类、序号、计划量(g)、出库量(g) | 名称、规格、应出量(份)、单价、本次出库(份)、金额、状态；缺口→汇总条 |
| 出库创建 Step2 | 已出（恒为 0）、可出量（改 max） | 同上 |

## 九、异常与边界

| 场景 | 处理 |
|---|---|
| 并发创建批次 | 同一排程单可被多批次拆分，但同一需求行的总分配份数不得超过需求量 → 事务内 `FOR UPDATE` 校验 |
| 并发确认批次 | 占用用条件更新（`reserved + X <= current`），失败抛「库存已变化，请重算」 |
| 库存不足 | 允许少出，差额记为缺口；批次行标红；履约进度显式标红 |
| 净料缺封装规格 | 拦截（现有行为） |
| 档案价缺失 | 行金额记 0 并标「价缺失」，不阻断出库 |
| 批次作废 | 释放全部占用；来源排程单回到「已确认」 |
| 出库单作废 | 回退已出库量、恢复库存、回写需求行（作废 ≠ 删除） |
| 需求日早于生产日 | 提示不拦截 |
| 自主备货行完成 | 入自由库存，不占用 |
