# 净菜库存管理 — 需求讨论记录

> 阶段一产出 · 2026-11-10 · 与张浩浩讨论并确认需求范围

---

## 一、需求原话

> 「完整放弃当前库存管理所有功能。当前切配中心的库存只用管理加工完成的净菜即可，也就是食材模块对应净料和小料的库存数据，统称为净菜。」

业务流程两条：

1. **入库线**：排程计划完成生产后，点击【完成生产】→ 明确当日切配工单是否完成，未完成净菜标注状态 → 提交后净菜自动入库 → 数据显示在当前库存列表。
2. **出库线**：点击创建出库单 → 选择门店和排程计划 → 自动带出该排程单所需切配工单数据 → 生成某门店的出库单，字段：一级分类、二级分类、序号、名称、份数、净料用量。
3. **特别要求**：出库单根据**实际入库数据**生成，排程单里没完成切配的必须明确体现。

## 二、现状盘点（代码核实结论）

| 现状 | 结论 |
|------|------|
| 库存管理 = 原料精确库存（`inventory` + `inventory_ledger`） | 全部废除 |
| 采购入库单确认即入原料库存 | 采购模块保留（凭证 + AI 识别），**不再联动库存** |
| 切配工单完成自动扣原料库存（`/api/inventory/out`） | 废除 |
| 切配工单（`cutting_orders`）已含净料(net) + 小料(minor) 两种来源，带一二级分类/编号/切配量(g)/切配份数 | **直接复用**，只需加完成确认字段 |
| 排程已有所属门店（`store_id`） | 出库单"选择门店"实为过滤条件，门店与排程天然绑定 |
| 排程详情已有【完成生产】按钮（直接把排程置"已完成"） | 改造为「完成生产确认」弹窗 |
| 小料此前按备货制不精确管理 | 本需求升级：小料与净料一起做精确库存 |

## 三、关键口径（本轮假设 ⚠️ 待张浩浩逐条确认）

| # | 议题 | 本轮采用口径 | 备选 |
|---|------|------------|------|
| 1 | 完成量口径 | 每行可填**实际完成量**（默认=需求量），支持部分完成 | 整单完成/未完成二元 |
| 2 | 提交次数 | **允许多次分批提交**：弹窗内每行三态（完成/未完成/**暂不确认**），暂不确认行保持 pending 留到下次；已完成/未完成行锁定 | 仅允许一次性提交 |
| 3 | 「未完成」语义 | 当日终态，锁定不可再改；想继续切需新一天排程 | 可反复翻回 pending |
| 4 | 排程完成条件 | 该排程全部切配工单达终态（完成或未完成）→ 排程自动「已完成」 | 以提交动作直接置完成 |
| 5 | 出库遇未完成/库存不足 | 按**可出量出库**（默认带出 min(需求, 可用库存)），未完成切配行标红、可出 0，允许改量确认 | 阻断出库 |
| 6 | 扣库存时机 | 创建出库单即扣减（事务内），作废时**回滚**库存（呼应红线：作废≠删除） | 确认收货再扣 |
| 7 | 库存单位 | 统一 **g**（与切配工单一致），≥1000g 展示自动换算「X 斤 Y g」 | 斤 |
| 8 | 批次管理 | 库存按净菜汇总一条（不分生产批次），追溯走台账 | FIFO 批次 |

## 四、用户故事

### 厨师长（PC）
- 作为厨师长，生产当天切配完成后，我在排程详情点【完成生产】，逐行确认每种净菜切了多少，没切完的标"未完成"并写原因，提交后净菜自动入库，我在库存列表立即可见。
- 作为厨师长，上午切完一部分我可以先提交入库，下午切完剩余部分再提交一次，系统只让我确认剩余的行。
- 作为厨师长，门店要货时我创建出库单，选门店和排程，系统自动按实际入库量算出每种净菜能出多少，没切配的货一眼能看到，确认后打印出库单交给司机。

### 切配师傅（被动使用）
- 每天照切配工单干活，完成量由厨师长回录，不需要自己操作系统。

## 五、范围

### 做
- 完成生产确认弹窗（实际量 / 未完成标注 / 分批提交）
- 净菜入库（自动）+ 当前库存列表
- 出库单创建（门店+排程 → 带出切配工单 → 按实际库存算可出量）/ 列表 / 详情 / 打印 / 作废回滚
- 净菜出入库流水（台账）
- 旧库存功能下线（页面/API/库存联动）

### 不做
- 原料库存（废除，非重构）
- 净菜成本/金额管理（价格体系留在食材档案）
- 批次/保质期/FIFO
- 门店收货确认环节（出库单即发货凭证）
- 库存预警/补货建议
- 移动端适配（PC 优先，与现系统一致）

## 第二轮讨论补充（2026-11-10 当日）

### 新决策（张浩浩）

1. **入库线移至生产计划单模块**：排程模块已新增「生产计划单」（跨店汇总进行中排程的切配工单，cuttingJson 快照）。【完成生产】及其确认弹窗放在生产计划单详情，不再放排程详情。排程详情的完成生产入口下线。
2. **库存单位拍板：按份出入库**（v1 口径表 #7 定了 g，本轮推翻）。每种净菜有封装规格（g/份），份数为记账主单位；g 作为辅助展示字段同步维护（出入库时按当时封装规格换算累加）。
3. **当前库存页去掉汇总 KPI 指标**；库存两个字段：**库存份数 + 库存量（g）**。
4. **出库单列表字段定稿**：序号、出库单号、门店、来源排程单名称、出库份数、合计金额、是否按计划出库、状态、库管负责人、创建时间、操作。
   - 「是否按计划出库」= 该排程切配工单计划数据与实际出库数据是否逐行一致（shipped == required）。
   - 「合计金额」依赖净料/小料档案的出库价（元/斤）链路：行金额 = 出库价 × 出库g ÷ 500。
   - 「库管负责人」= 出库单制单人（operator）。
5. **暂缓开发**：待排程模块（生产计划单）完成后进入开发。本轮只更新需求与功能设计。
6. **设计规范**：所有交互/视觉必须匹配现行系统（shadcn/ui、80px 图标侧边栏、卡片+表格、StatusBadge、Dialog 二次确认等）。

### 连带设计结论（依新决策推导）

- 完成生产确认单位 = **生产计划单汇总行**（跨店合并行）：按份录入实际完成份数（默认=计划份数），未完成标注原因；「暂不确认」行保持 pending 支持分批。
- 计划单完成后**回写**各店 cutting_orders：actualQty 按需求量占比分摊（展示级精度），status 随实际量置 completed / unfinished。
- 出库单明细：本次出库按**份**编辑（默认 min(计划份数, 库存份数)），行金额按当时出库价快照计算；是否按计划出库在创建时逐行比较得出并存储。
- 台账同时记份数与克重双单位。
