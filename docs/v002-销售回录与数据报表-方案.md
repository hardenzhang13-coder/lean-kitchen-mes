## 一、产品目标

1. **闭环**：每张排程单从「计划 → 采购 → 切配 → 生产 → 售出回录 → 复盘」在详情页内完整走完，回录是排程单的生命周期动作。
2. **决策**：数据报表回答两个问题——**哪些菜该加量/减量**（菜品销售）？**哪天的计划偏离最大**（排程复盘）？从而反哺次日排程。

### Success Metrics（v001 保留 + 新增）

| 指标 | 目标 |
|------|------|
| 回录及时率（生产日 22:00 前） | ≥ 90% |
| 回录入口点击 → 完成保存的转化率 | ≥ 85% |
| 报表打开 → 点击菜品/排程进详情（决策回流） | 周均 ≥ 10 次 |

### 2.2 排程详情页 `/schedules/[id]`（新增销售回录区块）

```
页头：← 返回  SCH-20261108-001  [进行中]        [打印] [导出] [销售回录（主按钮）]
信息卡片区：生产日期 | 门店 | 制单信息 | 菜品统计（现有 4 卡不动）
【v002 新增】待回录横幅（进行中且未回录时显示，amber 底色）：
  ⚠ 本排程尚未回录销售数据 · 回录后此处展示售出复盘  [去回录 →]
Tab 区（现有 3 个 + 新增 1 个）：
  排程菜单(8) | 切配工单明细(12) | 采购计划明细(15) | 销售回录(·)
                                                    ↑ 未回录时 amber 圆点徽标
销售回录 Tab 内容三态：
  · 未回录：空状态插画 + 「每天生产结束后，将各菜实际售出份数录回系统」+ [立即回录] 主按钮
  · 部分回录：「已回录 x/y 道」+ 已录菜品迷你表 + [继续回录]
  · 已回录：汇总 chips（售出/售出率/营收/实际毛利率）+ 复盘表（售出进度条/偏差/滞销标黄/超售标红）
           + 「最后回录 时间 · 操作人」+ [修改回录]
```

**回录弹窗**：与 v001 完全一致（手动录入 Tab + 批量导入 Tab），保存后刷新详情页销售回录区块与横幅。

### 2.3 数据报表 `/reports`（新页面）

```
页头：📊 数据报表    日期范围：[近7天|近30天|本月]    门店：华阳门店 ▾
Tab 1 菜品销售（默认）：
  汇总行：在售菜品 8 · 总售出 1,842 份 · 总销售额 ¥36,214 · 平均售出率 88.2% · 综合毛利率 54.1%
  表格（按销售额降序）：
  排名 | 菜品/类别 | 在售天数 | 计划份数 | 售出份数 | 售出率(进度条) | 销售额 | 毛利率 | 趋势(近4周售出率 sparkline)
  · 售出率<60% 行标黄 + 「滞销」badge
  · 行点击 → 菜品详情（后续迭代；v1 不可点）
Tab 2 排程复盘：
  表格（按日期倒序）：
  生产日期 | 编号 | 门店 | 菜品数 | 计划份数 | 售出份数 | 售出率 | 营收 | 回录状态(已回录/部分回录/未回录)
  · 点击行 → 对应排程详情页（决策回流）
```

**报表口径约定**：
- 仅统计**已回录**的排程明细；部分回录的排程按已录菜品计入并脚注说明；未回录排程不进报表但在排程复盘 Tab 显示「未回录」状态行（提醒闭环缺口）。
- 毛利 =（销售额 − 售出份数 × 菜品成本）/ 销售额；成本取菜品档案当前成本价（快照口径，v1 不做历史成本回溯）。
- 全部列表 API 分页（page/pageSize），禁止无分页。

## 三、页面流程

### 3.1 回录流程（v002 主链路）

```
排程列表 → 详情页 → （横幅/主按钮/Tab）→ 回录弹窗 → 手动录入 or CSV 导入
   ↓ 保存                                          ↓
详情页销售回录 Tab 切换为复盘视图 + 横幅消失      工作台当日卡片同步显示复盘数据
   ↓ 次日
厨师长 看 /reports 菜品销售 → 调整今日排程份数
```

### 3.2 状态机（不变，v001 保留）

明细行 `未回录(null) ⇄ 已回录(n)`；排程级派生 未回录 / 部分回录 / 已回录。

## 四、API 设计（新增 2 个，均为只读聚合）

### 4.1 POST /api/schedules/[id]/sold-records（v001 已定，不变）

### 4.2 GET /api/reports/dish-sales

```
?from=2026-11-01&to=2026-11-09&storeId=1&page=1&pageSize=20&sort=revenue_desc
→ { code, data: { list: [{ dishId, name, categoryName, days, planQty, soldQty, sellThrough, revenue, margin, trend:[...] }], total, page, pageSize } }
```
实现：schedule join schedule_item（status 已回录行）group by dish；trend 为近 4 周售出率数组（每周一个点，供 sparkline）。

### 4.3 GET /api/reports/schedule-review

```
?from&to&storeId&recordStatus=all|recorded|partial|none&page&pageSize
→ { list: [{ scheduleId, code, date, storeName, dishCount, planQty, soldQty, sellThrough, revenue, recordStatus }], total }
```
实现：schedule 级聚合，soldQty 仅统计已录行。

### 4.4 Schema（最终确认）

```prisma
model ScheduleItem {
  // 已有 actualSoldQty Decimal?
  soldRecordedAt DateTime? @map("sold_recorded_at")
  soldRecordedBy String?   @map("sold_recorded_by")
}
```
**无新表**。操作日志走 logOperation。
