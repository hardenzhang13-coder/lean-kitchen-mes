# 精益厨房 V3 — 交互视觉基线 v1

> 生效日期：2026-11-14  
> 状态：当前唯一基线。`ui-ux-standardization-spec.md`、`ui-ux-standardization-plan.md`、`ui-ux-standardization-supplement.md`、`ui-audit-report.md`、`component-layer-optimization-spec.md`、`table-form-optimization-spec.md`、`dialog-input-table-style-supplement.md` 均视为历史输入，不再作为执行依据。

## 0. 视觉升级层

本文档定义**信息架构与组件契约**，是执行依据；表层质感由轻拟物规范定义：

- `docs/light-skeuomorphism-baseline-v1.md`（v2 落地稿）：阴影 / 高光 / 按压反馈的 token 与组件规格。
- 两者不冲突：轻拟物只改视觉层，**不改**本文档的信息架构、页面形态、弹窗尺寸与操作语义。
- 两者冲突时，以本文档为准（例如弹窗尺寸、字号下限、分页形态仍按本文档执行）。

## 1. 目标

精益厨房是高频操作的内部业务系统。交互视觉优先服务三件事：

1. 快速扫读状态、数量和风险。
2. 明确当前能做什么、做完会发生什么。
3. 同类信息、同类动作、同类反馈在全系统保持一致。

页面可以因业务复杂度不同而采用不同骨架，但不能由业务页面临时发明基础形态。

## 2. 设计原则

| 原则 | 执行口径 |
|---|---|
| 信息优先 | 颜色、阴影和动效不得抢过数据与状态 |
| 结构稳定 | 同类页面使用固定入口、摘要区、内容区和操作区 |
| 单主操作 | 每个页面只有一个视觉主操作，其余动作降级 |
| 状态可追踪 | 提交、成功、失败、部分成功、作废都必须有明确反馈 |
| 异常可恢复 | 错误信息说明原因，并提供重试、修改或返回路径 |
| 桌面端优先 | 当前只验收桌面 Web；强调扫读、批量处理和稳定的工作区布局 |

## 3. 视觉 Token

### 3.1 颜色

- 品牌与主操作：`primary`
- 页面背景：`background`
- 内容容器：`card`
- 次要容器：`secondary` / `muted`
- 状态色只允许使用：`success`、`warning`、`danger`、`info`、`neutral`
- 状态底色使用对应的 `-muted` 或 `--status-*-bg`
- 业务分类色通过 `CategoryTag` 管理，不得复用状态色语义

### 3.2 字体

| 角色 | 规格 |
|---|---|
| 页面标题 | `text-2xl font-bold tracking-tight` |
| 区块标题 | `text-lg font-semibold` |
| 卡片/弹窗标题 | `text-base font-semibold` |
| 正文 | `text-sm` |
| 辅助信息 | `text-xs` |
| 数据数字 | 金额、数量、日期优先使用等宽数字或稳定列宽 |

正文不得小于 `12px`。数据密集表格可保留紧凑行高，但不得依赖过小文字承载关键信息。

### 3.3 尺寸与间距

| 场景 | 标准 |
|---|---|
| 页面边距 | `p-4` / `sm:p-6` / `lg:p-8` |
| 区块间距 | `gap-6` |
| 表单字段间距 | `gap-2` |
| 表单分区间距 | `gap-4` 至 `gap-6` |
| 常规控件高度 | `h-11` |
| 表格内紧凑控件 | 视觉高度可为 `h-8` / `h-9`，点击热区应接近 44px |
| 表格行高 | `DataTable` 默认 48px；食材等高密度扫读清单使用 `density="dense"`，行高约 44px |
| 桌面弹窗 | 使用语义尺寸，不直接声明像素宽度 |
| 标签 | 胶囊或小圆角，统一由组件控制 |

### 3.4 动效与焦点

- 微交互时长：150—250ms
- 只动画 `opacity`、`transform`、颜色和边框
- 支持 `prefers-reduced-motion`
- 键盘焦点必须可见
- 焦点、悬停、按下、禁用四种状态必须同时定义

#### 焦点统一口径（Tab 遍历）

全系统焦点指示只有两族，颜色统一取 `--sk-focus`（灰），禁止混用主题橙边框与发光环。

| 族 | 适用控件 | 指示样式 |
|---|---|---|
| 输入族 | `input`（文本类）/ `textarea` / `select` / `data-slot="input"` / `data-slot="textarea"` / `data-slot="select-trigger"` / `.skeu-input` / `.skeu-trigger` | 只把边框加深为 `--sk-focus`，不加发光环 |
| 按钮族 | `button` / 复选与单选框 / `data-slot="button"` / `role=button|link|tab|checkbox|radio` / `a` / `summary` | `outline: 2px solid var(--sk-focus)` + `outline-offset: 2px` |

- 字段型按钮（下拉触发器、筛选器）走输入族口径：在触发器上标 `data-focus="field"`，避免「描边 + 边框」双指示。
- 下拉项（`role="option"` / `role="menuitem"`）不套按钮族描边，保留自身的高亮底色。
- 语义状态优先于统一口径：采购录入的「低置信度」字段标 `data-low-confidence`，焦点时保留琥珀色边框与提示环。
- 规则写在 `app/globals.css` 的「焦点统一」段落；组件内不要再各自写 `focus:border-primary` / `focus-visible:ring-*`。

## 4. 语义化弹窗

业务页面使用 `AppDialogContent`，不得直接为 `DialogContent` 拼像素宽度。

| 尺寸 | 宽度 | 用途 |
|---|---:|---|
| `compact` | 400px | 删除、作废、清空等短确认 |
| `form` | 560px | 常规单列表单和短信息确认 |
| `wide` | 880px | 多列表单、预览和复杂选择 |
| `workbench` | 1200px | 左右布局、批量确认和高密度编辑 |

最终按 1280px、1440px、1920px 三档桌面宽度验收，不压缩字段。

自定义 `p-0` 布局（头部/底部固定、中部滚动的 workbench 形态）时，`AppDialogContent` 必须同时加 `overflow-hidden`，否则底部区域自有的背景色会盖住弹窗圆角，底角变成方形。标准件 `WorkbenchDialog` 已内置，直接复用。

## 5. 组件契约

| 组件 | 约束 |
|---|---|
| `PageShell` | 页面唯一外层；常规页面用 `content`，锁定高度的编辑页用 `workspace` |
| `PageHeader` | 页面唯一一级标题入口；统一承载返回、状态、说明和主操作 |
| `AppDialogContent` | 弹窗唯一尺寸入口；按语义选择 `compact` / `form` / `wide` / `workbench` |
| `FormSection` | 表单分区固定结构；桌面按 1/2/3/4 列组合 |
| `FormField` | 标签、必填、帮助和字段错误唯一入口 |
| `ListToolbar` | 列表搜索、筛选和重置唯一入口；放大镜图标内嵌在搜索框内（绝对定位），不作为输入框前的独立元素 |
| `DataTable` | 标准 CRUD 列表优先使用；复杂业务表可复用 Table 原语 |
| `StatusBadge` | 状态文字与语义色唯一映射入口 |
| `InfoTile` | 详情页摘要信息唯一入口 |
| `SectionTabs` | 内容分页唯一入口，支持键盘方向键 |
| `EmptyState` | 空数据唯一入口，必须说明原因和下一步；表格空数据保留表头，空态收进表体单元格（`DataTable` 内置，与 loading 态同构） |
| `LoadingState` | 异步加载唯一入口，按 table / list / card-grid / page / inline 选择 |
| `RecordSheet` / `RecordActions` | 半屏详情抽屉唯一入口；操作按 危险 / 次级 / 主操作 三槽分置；`headerAside` 承载关闭按钮下方的辅助信息 |
| `DetailSection` / `InfoCell` | 详情内容分组与双列信息单元唯一入口，不连续堆叠单行长列表 |
| `useRecordForm` | 表单状态唯一入口（初始化、dirty、字段错误、提交中、重置、连续录入） |
| `useRecordGuard` / `DiscardChangesDialog` | 未保存改动拦截唯一入口，关闭前必须确认 |
| `useRecordCopy` | 档案复制编排唯一入口（回填、名称后缀、弹窗叠放、提交后全关） |
| `PortionTag` | 份量枚举唯一渲染入口；枚举取值来自 `lib/shared/portion-scale.ts` |

> 组件的**工程与架构契约**（口径字典、模块形态、能力复用边界）见 [`docs/system-iteration-foundation-v1.md`](./system-iteration-foundation-v1.md)。

## 6. 页面模式

### 6.1 列表管理

固定顺序：

1. `PageHeader`：标题、说明、主操作。
2. `ListToolbar`：搜索、筛选、重置。
3. 内容：`DataTable` 或标准业务卡片。
4. `Pagination`。
5. 空、加载、错误状态。

列表卡片在桌面宽度下保持标题、状态和操作区清晰分区。

主数据清单（原料、净料、小料、调料、酱料、供应商、门店、单位、分类等）底部统一展示完整数据区间汇总和每页条数选择，不展示首页/尾页入口；抽屉内参照列表仍使用精简翻页，不为打开弹窗而改变标准列表的数据范围信息。`Pagination` 的 `totalLabel` / `showPageSize` 默认关闭，仅主数据清单启用；新增启用范围必须先改本节，再改代码。

分页底部形态（轻拟物视觉层，见 `light-skeuomorphism-baseline-v1.md`）：当前页用橙色胶囊单独表示，不再显示「当前页 / 总页数」；每页条数用胶囊触发器「N 条/页」，不再使用「每页显示 [N] 条」标签文案。

字段标题不携带单位，单位必须由数值行表达（列名 `净料单价`，值 `¥3.56/斤`）。表头统一加粗；字段必须单行完整显示，不使用省略号截断，也不通过换行压缩列宽；字段过多时优先删除非核心列，并允许表格局部横向滚动。点击整行进入详情，操作列不重复放置「查看」按钮；操作列直接展示当前行可执行的全部业务动作图标，不把动作折叠进「更多」菜单。删除操作统一收敛到详情页，列表操作列不提供删除入口（酱料在编辑弹窗底部提供）。没有独立详情页的简单主数据，删除允许放在列表操作列，但必须经二次确认，且不得进入编辑态。

**可排序清单**：字典类清单需要调整展示顺序时，操作列最左放上移 / 下移两个纯图标按钮（`SkeuIconAction`），首行禁用上移、末行禁用下移；搜索或状态筛选生效时整体禁用并提示「搜索时不可排序」——筛选隐藏了部分行，此时相邻目标不明确。排序以整表有序 id 列表提交（`PUT /api/{domain}/reorder`，事务内写 `sortOrder = 序号 + 1`），服务端须校验 id 覆盖全部在用行，否则拒绝并提示刷新。新增条目追加到末尾（`sortOrder = 当前最大值 + 1`），不得因默认 0 插到首位。

**列表卡片的内边距口径**：工具栏上下的留白必须相等，不得叠加多层内边距。标准写法是 `Card` 用默认 `py-5`/`gap-5`，`CardHeader` 写 `shrink-0 pb-0`，`CardContent` 写 `flex min-h-0 flex-1 flex-col px-4 pb-4`——工具栏上方 `py-5`(20px) 与下方 `gap-5`(20px) 对称。曾经的 `pb-3 + p-4` 写法会在下方叠出 48px，白占表格高度、把列表挤进内部滚动。

### 6.2 详情审阅

固定顺序：

1. `PageHeader`：返回、标题、状态、主操作。
2. 1—4 个 `InfoTile`：日期、制单人、来源、汇总数量。
3. `SectionTabs`。
4. 当前内容区。

危险操作与主操作分离。状态变化必须写清影响范围。

### 6.2.1 详情抽屉契约（通用）

主数据详情用半屏抽屉（`RecordSheet`，`50vw`），不用独立详情页；字段超过 8 个、存在多步骤或需要横向对照时才用独立页。

- 结构固定：抽屉头部（标题 + 编号 / 分类等 meta）→ 内容区 → 底部操作区（`RecordActions`）。
- 操作按三槽分置：`destructive`（删除，在左）/ `secondary`（复制、编辑）/ `primary`（主操作，在右）。危险操作与主操作分离。
- 内容用 `DetailSection` 分组，组内用 `InfoCell` 双列信息单元，不连续堆叠单行长列表。分组标题使用“基础信息 / 采购与计量 / 包装与规格 / 价格与成本”这类业务语义命名。
- 加载失败必须说明原因并给出下一步（关闭后重试 / 检查记录是否已删除），不空转。
- 只读 ↔ 编辑态切换时，若表单有未保存改动，关闭前必须经 `useRecordGuard` + `DiscardChangesDialog` 确认，不允许静默丢弃。
- 详情页顶部的关闭按钮下方可承载一条辅助信息（如建档时间），用 `RecordSheet` 的 `headerAside` 传入。
- 详情页触发的破坏性操作要说明影响范围与是否可恢复。

### 6.2.2 档案复制契约（通用）

复制是**新建动作**，不是编辑动作。

- 以现有档案为模板回填全部业务字段，原档案不受影响。
- 名称默认追加「-副本」以绕开重名校验拦截，用户可自行修改。
- 提交按新建处理，不带原记录 id。
- 从详情页触发复制时，复制表单以新弹窗叠在详情抽屉之上；提交成功后关闭全部弹窗。
- 列表操作列与详情页都可作为复制入口。
- 复制编排统一走 `useRecordCopy`，不在各页面各写一遍回填逻辑。

### 6.2.3 连续录入契约（通用）

批量录入场景支持「保存并继续添加」。

- 保存后保留分类、单位等不随条目变化的字段。
- 保存后清空名称、品牌、价格、供应商等每条都要重填的字段。
- 弹窗保持打开，并明确提示「已保存，可继续添加下一条」，不静默留在原地。

### 6.2.4 食材清单专有条款

以下条款只适用于食材库（食材 / 净料 / 调味品 / 调料 / 酱料），其它模块不套用。

- **搜索范围**：列表工具栏的关键词只匹配名称字段，不匹配编号、品牌/商品名称或别名；占位文案统一写「搜索名称...」。
- **主字段位置与强调**：主字段（名称）固定排在「序号、编号」之后；核心字段一律加粗并使用主题色（`font-semibold text-primary`），不得用普通正文样式。
- 食材清单突出食材名称、每斤单价；列表不展示入库单位。
- 调料清单突出食材名称、每斤单价。
- 净料清单突出名称、标准规格价。
- 净料列表不显示包装物料、包装尺寸。
- 食材清单的“商品名称”列统一命名为“品牌名称”；调料等自有口径模块保留原列名。
- 食材与调味品建档可填「出成率」（%）：放在表单「价格与出成率」分组，供应商字段归「基础信息」分组；两个清单均显示出成率列，转化净料/调料时预填且可修改（2026-11-26）。
- **出成率列排在每斤单价之前**（食材清单与调味品清单一致），未填时显示「—」。
- 调味品清单的「调料分类」用胶囊标签展示并按类型分色：单品调料 `amber`、复合调料 `violet`、成品酱料 `red`（`SeasoningTypeTag`）；调味品清单不展示「入库数量」。
- 调料产物清单（单品/复合/成品酱料）的「包装规格」列统一命名为「**规格**」，列位紧跟「调料名称」之后；表单内标签同步为「规格（g）」，计价提示中的「包装规格」一并改称「规格」。
- 转化/新建净料表单的份量默认取份量档案的基本单元行（单人份），档案不可达时兜底「单人份」。
- 食材列表的操作顺序为：编辑（默认动作按钮）、转化（primary 主操作最右）；行点击仍进入详情，操作列不再重复放查看（2026-11-25 拍板更新）。
- 调味品列表的操作顺序为：查看、编辑、转化（转化 = 转调料清单，同食材规范）。
- 净料列表的操作顺序为：打印标签、复制、编辑。
- 净料详情提供「使用概况」查看入口（操作区次级位），单品/复合/成品酱料清单在操作列提供同名入口；弹窗列出菜品编号、菜品名称、份量。数据口径：净料来自主料/辅料/小料（`dish_net_details` 的 role）引用关系，调料产物来自 `dish_seasoning_details.spec_id`。弹窗统一为 `MaterialUsageDialog`（FormDialog + AppDialogContent wide + DataTable）。
- 净料列表不显示封装加工费和出库价。
- 净料与净菜标签使用 `PortionTag` 展示份量，取值来自 `lib/shared/portion-scale.ts`。
- **建档时间**在详情页顶部（关闭按钮下方）展示，不在列表页出现。
- **分类三级口径（2026-11-28）**：食材/调味品建档的分类选择统一用 `CategoryCascadeSelect` 三级级联（三栏 + 列标题 +「不限三级」磁贴）；三级为可选层不做强限制——食材一二级必填、三级可选，调味品分类整体可空。净料表单三级用 `SelectField` 轻量下拉（转化时继承来源食材、可改）。
- **调味品清单「分类」列**展示调味品域分类（`一级 / 二级`），未挂分类显示「—」；工具栏配 `CategoryFilter` 筛选（domain=seasoning 树）。
- **设置页「原料分类」**统一管理食材/调味品两域分类（顶部 `SectionTabs` 域页签），伪树表格支持三级展开（一级 → 二级 → 三级），行操作含「添加二级 / 添加三级」。

### 6.3 创建编辑

- 超过 8 个字段、存在多步骤或需要横向对照时，使用独立页面。
- 简单 CRUD 表单使用弹窗。
- 简单主数据（≤5 个字段）使用 `RecordDialog` 的查看 / 新增 / 编辑三态，在同一个弹窗内切换，不照搬食材库的详情抽屉形态。
- 查看态用 `RecordView`（`DetailSection` + `InfoCell`）展示；底部只承载「关闭 / 编辑」。
- 新增与编辑态用 `SimpleForm`（单列、不分组、`gap-5`），底部只有「取消 / 保存」；删除等危险动作不得进入编辑态。
- 删除按模块放在列表操作列或查看态底部（设置模块放操作列），必须二次确认。
- 查看态关闭可直接进行；编辑态有未保存改动时，关闭或取消先经 `DiscardChangesDialog` 确认。
- 列表行点击进入查看态，操作列保留编辑、业务动作与删除。
- 页面结构固定为：`PageHeader`、基础信息、业务分区、操作区。
- 复杂表单使用 `FormSection`，在桌面宽度下按信息密度选择列数。
- 表单分组仅使用边框和标题建立层级，不使用浅色系分组背景。
- 提交中禁用重复提交；失败后保留用户输入；成功后明确跳转或关闭。

### 6.4 批量任务

- 先展示任务摘要和风险数量，再展示明细。
- 行级状态、批量确认、不可逆提示放在同一流程内。
- 部分成功必须单独提示，不得只显示笼统成功或失败。

## 7. 交互反馈

| 场景 | 标准反馈 |
|---|---|
| 首次加载 | 结构稳定的骨架屏 |
| 搜索/筛选 | 保留工具栏，只替换内容区 |
| 按钮提交 | 按钮禁用 + 加载图标 + 明确动词 |
| 成功 | Toast 或结果页，说明发生了什么 |
| 字段错误 | 错误靠近字段，提交后聚焦第一个错误 |
| 请求失败 | 错误原因 + 重试或修改路径 |
| 破坏性操作 | 说明影响、是否可恢复、默认焦点不落在危险按钮 |
| 无数据 | 原因说明 + 主动作 |

## 8. 桌面 Web 与可访问性

- 当前只做桌面 Web，不纳入手机或 PWA 适配验收。
- 按 1280 / 1440 / 1920 宽度验证页面级无横向滚动；数据表格允许局部横向滚动。
- 所有表单控件有可见标签。
- 图标按钮必须有 `aria-label` 或可见文字。
- Tab 使用 `role="tablist"` 与 `aria-selected`，支持方向键。
- 颜色不得作为唯一状态信号，状态标签必须带文字。
- 弹窗支持 Esc 关闭，并保留清晰的取消路径。

## 9. 治理规则

1. 新页面只允许从上述页面模式组合，不新造基础操作形态。
2. 业务页面不得直接定义状态色、弹窗像素宽度和表单分区列数。
3. 新增组件变体必须同时提供使用场景、桌面布局表现和状态样张。
4. `/ui-kit` 是组件的可视验收页，组件改动必须同步样张。
5. 旧规范文档中的冲突内容不得继续引用。
6. 每轮迭代重点回归排程、采购、生产计划、库存四条核心链路。
7. 跨模块使用的枚举必须定义在 `lib/shared/`，并同时提供「枚举值数组 + 选项元数据 + 取值解析 + 合法性判断 + 渲染组件」五件套；服务端 zod enum 与前端选项从同一份导入，不得各写一份字面量。
8. 跨业务域引用必须走 `app/components/ui/` 或 `lib/shared/`，禁止 `app/components/<域A>/` 直接 import `app/components/<域B>/`。
9. 通用层组件自身必须满足基线（不得直写弹窗像素宽度、不得小于 12px 字号）；改通用件必须回归它的全部调用方，不接受「看起来差不多」。
10. 枚举或口径重构时，存量迁移必须走显式 UPDATE 映射表并保留旧值解析兼容，迁移前先做只读盘点确认存量取值集合。

## 10. v1 试点范围

- 排程列表：页面标题操作区、列表状态、标准 Tab、加载与空状态。
- 生产计划详情：详情页面骨架、摘要信息、Tab、语义弹窗。
- 采购录入：编辑工作台骨架、表单分区、空状态和弹窗尺寸。
- `/ui-kit`：基线组件与状态的统一可视样张。

模块改造的批次顺序与每批验收标准见 [`docs/system-iteration-foundation-v1.md`](./system-iteration-foundation-v1.md) §5。
