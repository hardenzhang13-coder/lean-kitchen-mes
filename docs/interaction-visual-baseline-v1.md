# 精益厨房 V3 — 交互视觉基线 v1

> 生效日期：2026-11-14  
> 状态：当前唯一基线。`ui-ux-standardization-spec.md`、`ui-ux-standardization-plan.md`、`ui-ux-standardization-supplement.md`、`ui-audit-report.md`、`component-layer-optimization-spec.md`、`table-form-optimization-spec.md`、`dialog-input-table-style-supplement.md` 均视为历史输入，不再作为执行依据。

## 1. 目标

精益厨房是高频操作的内部业务系统。交互视觉优先服务三件事：

1. 快速扫读状态、数量和风险。
2. 明确当前能做什么、做完会发生什么。
3. 同类信息、同类动作、同类反馈在全系统保持一致。

页面可以因业务复杂度不同而采用不同骨架，但不能由业务页面临时发明基础形态。

## 2. 设计原则

| 原则 | 执行口径 |
|---|---|
| 信息优先 | 颜色、阴影和动效不得抢过数据与状态 |
| 结构稳定 | 同类页面使用固定入口、摘要区、内容区和操作区 |
| 单主操作 | 每个页面只有一个视觉主操作，其余动作降级 |
| 状态可追踪 | 提交、成功、失败、部分成功、作废都必须有明确反馈 |
| 异常可恢复 | 错误信息说明原因，并提供重试、修改或返回路径 |
| 桌面端优先 | 当前只验收桌面 Web；强调扫读、批量处理和稳定的工作区布局 |

## 3. 视觉 Token

### 3.1 颜色

- 品牌与主操作：`primary`
- 页面背景：`background`
- 内容容器：`card`
- 次要容器：`secondary` / `muted`
- 状态色只允许使用：`success`、`warning`、`danger`、`info`、`neutral`
- 状态底色使用对应的 `-muted` 或 `--status-*-bg`
- 业务分类色通过 `CategoryTag` 管理，不得复用状态色语义

### 3.2 字体

| 角色 | 规格 |
|---|---|
| 页面标题 | `text-2xl font-bold tracking-tight` |
| 区块标题 | `text-lg font-semibold` |
| 卡片/弹窗标题 | `text-base font-semibold` |
| 正文 | `text-sm` |
| 辅助信息 | `text-xs` |
| 数据数字 | 金额、数量、日期优先使用等宽数字或稳定列宽 |

正文不得小于 `12px`。数据密集表格可保留紧凑行高，但不得依赖过小文字承载关键信息。

### 3.3 尺寸与间距

| 场景 | 标准 |
|---|---|
| 页面边距 | `p-4` / `sm:p-6` / `lg:p-8` |
| 区块间距 | `gap-6` |
| 表单字段间距 | `gap-2` |
| 表单分区间距 | `gap-4` 至 `gap-6` |
| 常规控件高度 | `h-11` |
| 表格内紧凑控件 | 视觉高度可为 `h-8` / `h-9`，点击热区应接近 44px |
| 表格行高 | `DataTable` 默认 48px；食材等高密度扫读清单使用 `density="dense"`，行高约 44px |
| 桌面弹窗 | 使用语义尺寸，不直接声明像素宽度 |
| 标签 | 胶囊或小圆角，统一由组件控制 |

### 3.4 动效与焦点

- 微交互时长：150—250ms
- 只动画 `opacity`、`transform`、颜色和边框
- 支持 `prefers-reduced-motion`
- 键盘焦点必须可见
- 焦点、悬停、按下、禁用四种状态必须同时定义

## 4. 语义化弹窗

业务页面使用 `AppDialogContent`，不得直接为 `DialogContent` 拼像素宽度。

| 尺寸 | 宽度 | 用途 |
|---|---:|---|
| `compact` | 400px | 删除、作废、清空等短确认 |
| `form` | 560px | 常规单列表单和短信息确认 |
| `wide` | 880px | 多列表单、预览和复杂选择 |
| `workbench` | 1200px | 左右布局、批量确认和高密度编辑 |

最终按 1280px、1440px、1920px 三档桌面宽度验收，不压缩字段。

## 5. 组件契约

| 组件 | 约束 |
|---|---|
| `PageShell` | 页面唯一外层；常规页面用 `content`，锁定高度的编辑页用 `workspace` |
| `PageHeader` | 页面唯一一级标题入口；统一承载返回、状态、说明和主操作 |
| `AppDialogContent` | 弹窗唯一尺寸入口；按语义选择 `compact` / `form` / `wide` / `workbench` |
| `FormSection` | 表单分区固定结构；桌面按 1/2/3/4 列组合 |
| `FormField` | 标签、必填、帮助和字段错误唯一入口 |
| `ListToolbar` | 列表搜索、筛选和重置唯一入口 |
| `DataTable` | 标准 CRUD 列表优先使用；复杂业务表可复用 Table 原语 |
| `StatusBadge` | 状态文字与语义色唯一映射入口 |
| `InfoTile` | 详情页摘要信息唯一入口 |
| `SectionTabs` | 内容分页唯一入口，支持键盘方向键 |
| `EmptyState` | 空数据唯一入口，必须说明原因和下一步 |
| `LoadingState` | 异步加载唯一入口，按 table / list / card-grid / page / inline 选择 |

## 6. 页面模式

### 6.1 列表管理

固定顺序：

1. `PageHeader`：标题、说明、主操作。
2. `ListToolbar`：搜索、筛选、重置。
3. 内容：`DataTable` 或标准业务卡片。
4. `Pagination`。
5. 空、加载、错误状态。

列表卡片在桌面宽度下保持标题、状态和操作区清晰分区。

`Pagination` 全站统一只保留“上一页 / 当前页 / 下一页”，不显示每页条数选择、当前数据区间、首页和尾页入口；标准列表与抽屉内参照列表必须保持相同底部高度。

### 6.2 详情审阅

固定顺序：

1. `PageHeader`：返回、标题、状态、主操作。
2. 1—4 个 `InfoTile`：日期、制单人、来源、汇总数量。
3. `SectionTabs`。
4. 当前内容区。

危险操作与主操作分离。状态变化必须写清影响范围。

食材清单详情使用半屏抽屉（`50vw`），按“基础信息 / 采购与计量 / 包装与规格 / 价格与成本”分组，字段使用双列信息单元，不连续堆叠单行长列表。

### 6.2.1 食材清单

- 表头统一加粗。
- 字段必须单行完整显示，不使用省略号截断，也不通过换行压缩列宽；字段过多时优先删除非核心列，并允许表格局部横向滚动。
- 原料清单突出食材名称、每斤单价。
- 净料清单突出名称、标准规格价。
- 净料与小料列表不显示包装物料、包装尺寸。
- 所有列表页字段标题不携带单位；单位必须由数值行表达，如 `净料单价` 列的值为 `¥3.56/斤`、`标准规格价` 列的值为 `¥4.50/份`。
- 查看详情通过点击整行进入，操作列不重复放置“查看”按钮。
- 操作列直接展示当前行可执行的全部业务动作图标，不把动作折叠进“更多”菜单。
- 原料列表的操作顺序为：编辑、转净料、删除。
- 净料列表不显示封装加工费和出库价。

### 6.3 创建编辑

- 超过 8 个字段、存在多步骤或需要横向对照时，使用独立页面。
- 简单 CRUD 表单使用弹窗。
- 页面结构固定为：`PageHeader`、基础信息、业务分区、操作区。
- 复杂表单使用 `FormSection`，在桌面宽度下按信息密度选择列数。
- 提交中禁用重复提交；失败后保留用户输入；成功后明确跳转或关闭。

### 6.4 批量任务

- 先展示任务摘要和风险数量，再展示明细。
- 行级状态、批量确认、不可逆提示放在同一流程内。
- 部分成功必须单独提示，不得只显示笼统成功或失败。

## 7. 交互反馈

| 场景 | 标准反馈 |
|---|---|
| 首次加载 | 结构稳定的骨架屏 |
| 搜索/筛选 | 保留工具栏，只替换内容区 |
| 按钮提交 | 按钮禁用 + 加载图标 + 明确动词 |
| 成功 | Toast 或结果页，说明发生了什么 |
| 字段错误 | 错误靠近字段，提交后聚焦第一个错误 |
| 请求失败 | 错误原因 + 重试或修改路径 |
| 破坏性操作 | 说明影响、是否可恢复、默认焦点不落在危险按钮 |
| 无数据 | 原因说明 + 主动作 |

## 8. 桌面 Web 与可访问性

- 当前只做桌面 Web，不纳入手机或 PWA 适配验收。
- 按 1280 / 1440 / 1920 宽度验证页面级无横向滚动；数据表格允许局部横向滚动。
- 所有表单控件有可见标签。
- 图标按钮必须有 `aria-label` 或可见文字。
- Tab 使用 `role="tablist"` 与 `aria-selected`，支持方向键。
- 颜色不得作为唯一状态信号，状态标签必须带文字。
- 弹窗支持 Esc 关闭，并保留清晰的取消路径。

## 9. 治理规则

1. 新页面只允许从上述页面模式组合，不新造基础操作形态。
2. 业务页面不得直接定义状态色、弹窗像素宽度和表单分区列数。
3. 新增组件变体必须同时提供使用场景、桌面布局表现和状态样张。
4. `/ui-kit` 是组件的可视验收页，组件改动必须同步样张。
5. 旧规范文档中的冲突内容不得继续引用。
6. 每轮迭代重点回归排程、采购、生产计划、库存四条核心链路。

## 10. v1 试点范围

- 排程列表：页面标题操作区、列表状态、标准 Tab、加载与空状态。
- 生产计划详情：详情页面骨架、摘要信息、Tab、语义弹窗。
- 采购录入：编辑工作台骨架、表单分区、空状态和弹窗尺寸。
- `/ui-kit`：基线组件与状态的统一可视样张。

试点验证通过后，再按模块逐步替换其余页面，不进行一次性全站重写。
